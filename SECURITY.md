# Security Policy

## Supported versions

| Version | Supported |
| ------- | --------- |
| `main` branch | ✅ |

This is a documentation-only curated list. There is no executable code, and no supported versions of any software are distributed.

## Reporting a vulnerability

Please **do not** open a public issue or PR for security problems.

Use GitHub **private vulnerability reporting**: go to the repository → **Security and quality** tab → **Report a vulnerability**.

Include: the affected file/link, steps to reproduce, and the impact you observed. We will acknowledge within 3 business days and coordinate a fix/disclosure timeline with you.

If private vulnerability reporting is unavailable (not yet enabled), do not post details publicly — open a minimal issue titled `security report — please enable private reporting` with no technical details, and we will follow up privately.

## Scope

In scope: repository content (README links/descriptions), maintainer workflows, and any future CI. Content-integrity reports are in scope when a listing presents AI-generated content as scholar-reviewed, misattributes religious authority, or makes an authenticity claim without evidence — report privately with the affected README link. Out of scope: the content of third-party sites linked from this list (report those to the site owner), and social-engineering attacks against maintainers.
